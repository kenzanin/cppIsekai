# clang-doc generation

Generated by `xmake doc` into `docs/api/` (gitignored). `XMAKE_DOC_FORMAT=md` selects markdown.

## D1 — html and md must each come out of ONE process
`--executor=all-TUs` writes per-TU JSON intermediates, but this clang-doc (LLVM 23.1.5) cannot
render them back: handing it a `.json` input answers `Reducing 0 infos` and emits nothing. So the
whole doc set is produced by a single invocation that parses every TU (44 in src/), which is slow
(~48s for a store TU) but is the only path that yields html/md.

## D2 — out-of-project includes are rewritten to -isystem
xmake passes xrepo package includes as `-I`, so clang-doc documents sqlite_orm, crow, asio, boost,
std, sol as if they were project code (1816 pages for one TU, 8.1 MB of html). Rewriting every
include dir outside the project — and everything under `third_party/` (cdp-cpp, traypp, wasm3) — to
`-isystem` drops them: same TU yields 26 pages, and the md tree falls from 1.8 MB to 420 KB.
The rewritten database lives in `build/clangdoc/compile_commands.json`.

## D3 — md needs a private prefix
The distro llvm package installs only the html mustache templates under `/usr/share/clang-doc`;
`--format=md` dies on "cannot open .../share/clang-doc/md/class-template.mustache". The five md
templates are vendored in `scripts/clang-doc/md/` and the task assembles
`build/clangdoc/tool/{bin,share}` (a copy of the binary plus both template sets), then passes
`--extra-arg=-resource-dir=$(clang -print-resource-dir)` because a copied clang-doc resolves
`../lib/clang/<ver>` relative to its own argv[0] and otherwise cannot find `stddef.h`.

## Consequences
- `--public` only: the output is the API surface (decls + `/** \brief */` comments), not bodies.
- md file names are mangled USRs; navigate via `all_files.md` / `index.md` or grep, not by filename.
- md is the better AI-consumption format (plain text, grep-able, ~1-3 KB per page vs 15-30 KB of markup).
