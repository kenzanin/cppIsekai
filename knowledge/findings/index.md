# Findings
* [Host image fetch is plugin-blind: no Referer (js mangatown pilot finding)](js-image-referer-gap.md) - Image CDNs that require Referer 403 through the host cache/reader path; fix = per-plugin image-referer plumbed to the img fetcher.
* [status_flags: followup gaps left open by the detail-source-of-truth fix (c0fce4e)](library-status-flags-followups.md) - RESOLVED 2026-11-14 by change status-flags-followup-cleanup: the scheduler chapters-only path now advances total_ch/bit0; the store flag lifecycle, inject_status_flags and detail-page badge bits are test-locked. Complete became bit5 of a one-hot category set (not a standalone bit2), dim moved to bit6, and has_update was dropped after a backfill. Superseded by architecture/status-flags-bitfield and findings/status-flags-apply-migration-order.
* [status-flags apply: backfill must precede DROP COLUMN has_update (18/31 rows at risk)](status-flags-apply-migration-order.md) - Applying status-flags-followup-cleanup closed G1-G5 and exposed that the has_update drop must be preceded by a status_flags backfill: the live DB had 18/31 rows with has_update=1 and no status_flags column, so dropping first would have erased the New badge for those rows.
* [Delegating to a free model: native subagent skill beats spawn_agents (no model field)](free-worker-routing.md) - Free-model work can be delegated two verified ways (native Reasonix skill with runAs:subagent + model 9router/free, or opencode run -m 9router/free), while the spawn_agents tool has no model field at all; configured model names live in ~/.config/opencode/opencode.json.
* [Rec backlog triage: 2 items already done, A7 proven bug, 3 OpenSpec changes opened](rec-backlog-triage.md) - Triage of the two recommendation backlogs against the tree: A3 (precompressed assets) and U6 (settings provenance) already shipped, A6 closed, A7 proven to be a real silent bug (ch1000 exported ahead of ch999, offsets 67 vs 154), A5 half-true (detection works, escape hatch hides it); three OpenSpec changes opened - cbz-chapter-order, ui-polish, refactor-hygiene.
* [xmake cxx_bin: def-time add_ldflags can drop flags; on_load t:add is the reliable route](xmake-ldflags-on-load-hook.md) - In the shared cxx_bin helper, flags added via def-time add_ldflags(..., {force=true}) can silently miss the link command (-rdynamic was dropped while CURL_SO from the very same call landed); the proven route is t:add('ldflags', ..., {force=true}) inside the target on_load hook, the same path that injects -fuse-ld=mold.
* [Detail vs library title mismatch: fixed (glaze map insert invalidated the title view)](detail-name-vs-library-card.md) - Detail h1 was empty ('…') while the library card showed a title. Root cause was NOT the api_cache jsonb/ok theory recorded on 2026-11-15: json_type(payload,'$.ok') is 'true' and json(payload) emits literal true, so envelope_ok always passed. The real bug was inside apply_chosen's ensure_name() (src/http/enrich_internal.hpp): 'd["name"].data = *s' assigned through a reference into the SAME glaze object, and glaze's object_t is a flat map (ordered_small_map) whose insertion of "name" relocates the title node -- the assignment then read moved memory and wrote an empty name (live /api/detail showed "name":""). Fixed by copying the title into a local std::string first; regression test 'apply_chosen derives detail name from the scraper title' added. Committed 9966ecb.
* [Phantom test crashes were gdb-session artifacts; verify plain-run first](test-crashes-gdb-artifact.md) - test_plugin/test_htmltext SIGSEGVs seen only in gdb sessions (sol2 closure dtor, _Rb_tree::_M_erase, garbage this) never reproduced on plain runs; suite 18/18 green twice - dig backtraces only on a plain-run repro.
* [mangasushi: 2 covers 404, upstream case-renamed files, daemon emits stale lowercase URLs](mangasushi-cover-404-case-rename.md) - Seisan/LONELY covers 404 on /cache/img: upstream case-renamed files; api_cache, fetch-stack lowercasing and stale installed plugin copy (data/plugins == plugins_dev, byte-identical) all ruled out; only CF edge variant per TLS fingerprint (chrome116) remains unproven.
* [/plugins/reload segfaults the cppIsekai daemon](plugins-reload-segfault.md) - Historical: /plugins/reload used to SIGSEGV because the daemon was built with GCC (sol2 lambda-name collision). Resolved by the clang toolchain — reload now returns 200 over repeated calls; do not follow the old 'never call reload' rule.
* [host.re2.find_all is 1-indexed in Lua: m[1] = full match, groups start at m[2]](re2-findall-one-indexed.md) - sol2 marshals the C++ vector<vector<string>> [full, g1, ...] to a 1-based Lua table, so plugins written with Go-style indexing are off by one.
* [valid_title_pair rejects real-world manga slugs (apostrophes, exclamation marks)](valid-title-pair-charset.md) - valid_title_pair whitelist blocked real slugs; replaced 2026-11-16 with a denylist (reject / \ ? # %, space, C0/DEL, dot segments) — unicode and punctuation pass.
* [Lua plugin end-to-end audit 2026-11-16 (search/detail/chapters/save)](lua-plugin-audit-2026-11-16.md) - Audit of all 29 Lua scraper plugins through the daemon routes after fixes: 21 pass fully, 8 fail now (all upstream blocks, no code bug in 7 of them).
* [sol2 3.5.0 functor teardown corruption is GCC-only (clang builds are safe)](sol2-lua-functor-teardown-corruption.md) - Resolved: sol2 3.5.0 keys functor metatables on __PRETTY_FUNCTION__, which GCC renders identically for every same-signature lambda (clang includes source location) -> wrong destructor at lua_close. cppIsekai builds with clang, so no collision; verified green teardown + reload. Found and fixed a real dangling [&cfg]/[&params] capture in install_host_tools.
* [1manga.co scraping quirks (HTML port)](1manga-site-quirks.md) - 1manga.co's GraphQL backend rejects external clients; every feature is reachable by scraping the server-rendered HTML. Records the markup/selector traps the Lua port had to handle.
